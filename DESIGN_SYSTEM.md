# Design system — clinic-v2.html

Дата: 2026-07-30. Дизайн-дайлы по ТЗ: variance 5/10 (сбалансировано, не минимализм и не brutalism), motion 3/10 (сдержанно), density 4/10 (стандартная, не dashboard-плотная). Направление: спокойный современный минимализм с умеренной цветностью и лёгкой глубиной.

**Как использован nextlevelbuilder/ui-ux-pro-max-skill.** Запущен `search.py --design-system --variance 5 --motion 3 --density 4` с ключевыми словами продукта («medical clinic patient tracker dashboard operational tool»). Инструмент предложил стиль *Data-Dense Dashboard* — это совпадает с тем, что уже было в проекте (панель KPI-сегментов + плотный список), и Pre-Delivery Checklist (без emoji-иконок, hover 150–300 мс, контраст 4.5:1, focus-состояния, `prefers-reduced-motion`, брейкпоинты 375/768/1024/1440) — он взят как есть и применён (см. ниже). Предложенную инструментом цветовую пару (медицинский teal/cyan + зелёный акцент) и шрифты Figtree/Noto Sans — **не применяли**: у проекта уже есть согласованная с пользователем индиго-палитра и IBM Plex Sans/Mono, привязанная к реальному фиолетовому логотипу МКНЦ (см. `PROJECT_BRIEF_V2.md`), и замена на случайную teal-палитру инструмента конфликтовала бы с уже утверждённым брендом. Механически весь вывод инструмента не копировался — использованы только те части, что не противоречат уже принятым решениям.

## Цветовые токены

Два источника истины: `:root` (светлая тема) и `:root[data-theme="dark"]` в `clinic-v2.html`. Один акцент, семантические цвета отдельно от него.

| Роль | Светлая | Тёмная | Назначение |
|---|---|---|---|
| `--bg-page` | `#F2F3F8` | `#12141F` | фон страницы, с холодным индиго-подтоном, не чистый серый |
| `--surface` / `--surface-alt` | `#FFFFFF` / `#F8F9FC` | `#1A1D2B` / `#232738` | карточки / вложенные панели |
| `--border-color` | `#E2E4EE` | `#2B2F42` | разделители |
| `--text-primary/body/secondary/tertiary` | `#171B2C … #8A90AD` | `#E7E9F5 … #6C7292` | 4-ступенчатая иерархия текста |
| `--accent` | `#4F46E5` | `#8B84F4` | единственный основной цвет — привязан к логотипу МКНЦ |
| `--danger` / `--warning` / `--good` (+ `-soft`/`-fill`) | `#B42318` / `#92400E` / `#15703F` | `#F2867A` / `#F0B559` / `#6FCB9A` | статусы (просрочено/скоро/в норме) — независимы от акцента |
| `--chip` / `--neutral-fill` | `#EDEEF5` / `#C7CADA` | `#232637` / `#3A3F58` | нейтральные чипы/полосы без категориального смысла |

Правило: цвет никогда не единственный носитель статуса — везде рядом текст или точка-индикатор (`.date-indicator-dot`), не голая заливка.

## Типографика

- **Интерфейс/заголовки**: IBM Plex Sans, 400–700. **Числа** (возраст, дни, коды МКБ-10, таймстампы): IBM Plex Mono 500, `font-variant-numeric: tabular-nums` — колонки цифр не «пляшут».
- Оба шрифта встроены как base64 `@font-face` (кириллица + латиница отдельными `unicode-range`) — файл остаётся офлайн-самодостаточным, без запроса к Google Fonts во время работы.
- Масштаб: 21px заголовок страницы → 16px имя пациента → 13–14px основной текст → 10.5–12px метки/чипы. Тело нигде не мельче 10.5px (мелкие подписи в чипах — осознанное исключение для очень плотных вспомогательных меток, не основного текста).
- `line-height` тела 1.4–1.5.

## Отступы, радиусы, тени

- Радиусы различаются по смыслу, а не одинаковые везде: 6px — поля/кнопки/сегменты сводной панели; 12px — карточки-контейнеры (панель сводки, список, модалки, `login-box`); 999px (pill) — бейджи/чипы/значки статуса, где скругление означает «это тег», а не «это карточка».
- Полоса приоритета на строке пациента — `border-left: 3px solid`, БЕЗ скругления с этой стороны (скруглённый однобортовый акцент выглядит «приклеенным»).
- Тени — 3 уровня (`--shadow-sm/md/lg`), только у карточек-контейнеров верхнего уровня; строки списка внутри — без собственной тени, разделены hairline-бордером (плотный список, не стопка карточек с тенями).

## Иконки

Правило проекта: иконка — только если ускоряет распознавание действия или показывает статус; иначе текстовая подпись. Результат: во всём интерфейсе — одна инлайновая SVG-иконка (лупа в поле поиска) и три монохромных типографских символа как функциональная, не декоративная иконография — `✓` (пройденный этап), `✕` (удалить событие), `▼`/`▲` (разворот карточки). Ни одного emoji. Все icon-only кнопки (`✕`, шеврон разворота) получили `aria-label`/`title` — см. `SECURITY_AUDIT.md` не про это, но фикс сделан в рамках этой же задачи (accessibility-проход).

## Компоненты

- **Сводная панель** (`.stats-bar`): 4 строки-метра (приоритет/этапы/срок/заведующий) — сегменты пропорциональны количеству пациентов (кроме «заведующий» — равные сегменты, т.к. ширина по числу пациентов «сплющивала» бы длинные фамилии); плоские смысловые заливки вместо градиентов.
- **Список пациентов**: один общий контейнер с тенью, строки внутри — hairline-разделители, без собственных теней/скруглений по бокам. Число+единица времени всегда моно-шрифтом.
- **Формы**: постоянные видимые `<label>` (не placeholder-as-label), обязательные поля помечены `*`, фокус — `box-shadow` кольцо в цвет акцента (не браузерный дефолт, но и не убран без замены — проверено по всем трём местам, где стоял `outline: none`).

## Анимация (motion 3/10)

- Переходы 150–300 мс (`transition: all 0.15s/0.2s` на кнопках/полях), без bounce/zoom/вращений.
- Ровно две keyframe-анимации во всём файле: мягкая пульсация точки просроченного/срочного дедлайна (`gentle-pulse`, только opacity, 2.4s) и пульсация кольца у «следующего доступного» этапа таймлайна (`pulse-next`). Обе не анимируют layout (width/height), только opacity/box-shadow.
- Добавлен глобальный `@media (prefers-reduced-motion: reduce)` — гасит все анимации/переходы до почти нуля для пользователей с этой настройкой ОС (этого не было до данной задачи — добавлено в рамках UX-прохода).

## Адаптивность

Проверено без горизонтального скролла на 375 / 768 / 1024 / 1440px (замер `scrollWidth` vs `innerWidth` в браузере, не только визуально). На узких экранах шапка (`.topbar`) и заголовок страницы (`.pagehead`) переходят в колонку; сегментные метры сводной панели, где сегментов много (этапы, срок, заведующий), скроллятся горизонтально внутри своей строки (`overflow-x: auto`) вместо сжатия подписей до нечитаемости — кнопка «Все» вынесена за пределы скролл-зоны и всегда видна.

## UX-решения, специфичные для приложения (не из общего чек-листа)

- Цвет вертикальной полосы приоритета на строке пациента буквально совпадает с цветом сегмента «Приоритет» в сводной панели сверху — один источник цвета, не два независимых.
- Индикатор срока (красная точка) сознательно **не** перекрашивается по приоритету пациента — красный зарезервирован только за предупреждением о дедлайне, иначе «срочный» пациент с датой через 3 недели читался бы так же тревожно, как реально просроченный.
- Таймлайн-узлы этапов (кружки 1–7) получили `role="button" tabindex="0"` и обработку Enter/Space — раньше это была кликабельная `<div>` без клавиатурной альтернативы, единственное реально узкое место keyboard-навигации в приложении (исправлено в рамках этой задачи, см. `SECURITY_AUDIT.md`/отчёт).
