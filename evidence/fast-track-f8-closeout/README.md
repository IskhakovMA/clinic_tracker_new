## Первопричина и исправление

На одном бинарнике Chromium 151.0.7922.34 в Linux x86_64 воспроизведен `socket_path_too_long`. При старой форме TMPDIR длиной 67 байт измерены 105 байт профиля и 113 байт фактического пути сокета, код 1. При TMPDIR длиной 16 байт тот же браузер запустился с кодом 0. Исходный stderr старого задания не сохранился. Контрольный эксперимент подтверждает механизм отказа для прежней конфигурации путей.

Runner использует короткий закрытый Linux TMPDIR для Chromium, а синтетическая SQLite остается в прежнем изолированном каталоге. Ранний отказ оставляет очищенную квитанцию и ненулевой статус. При отказе запуска потока чтения журнала уже запущенный синтетический сервер завершается и дожидается очистки. Workflow совпадает с приложенным YAML. В приложенном Python внесена эта узкая проверенная поправка.
