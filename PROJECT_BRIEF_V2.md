# clinic-v2.html — бриф для продолжения работы

## Что это
Альтернативная визуальная версия того же приложения (см. `PROJECT_BRIEF.md` — там весь функционал и его история). Это **не новый проект и не отдельная ветка развития** — это редизайн существующего `clinic.html` поверх той же логики, чтобы можно было сравнить два визуальных языка на живом приложении и выбрать один.

## Статус: на согласовании
Сейчас в проекте временно сосуществуют два файла:
```
clinic-tracker-python/clinic.html     — текущий вид (не тронут)
clinic-tracker-python/clinic-v2.html  — новый вид (этот бриф)
```
Пользователь сравнивает обе версии вживую и сообщит, какую оставить. **Когда решение будет принято** — либо `clinic-v2.html` заменяет `clinic.html` (с переносом истории функционала в основной бриф), либо `clinic-v2.html` и этот файл удаляются. До этого момента — не удалять и не сливать самостоятельно.

## Как получен
1. Пользователь показал скилл `web-artifacts-builder` и попросил предложить дизайн для будущей полноценной веб-версии трекера (сейчас один HTML-файл, веб-сервис — дело будущего, см. «Другие известные ограничения» в основном брифе).
2. Сначала был согласован **дизайн-макет** (статический HTML, без функциональности) — палитра/шрифты/раскладка главного экрана (список пациентов + сводная панель), показан пользователю и одобрен.
3. По просьбе «давай соберём на этом дизайне, сохранив полностью весь функционал» дизайн применён **поверх копии `clinic.html`** (не переписан с нуля на React) — это резко снижает риск потерять что-то из уже накопленной функциональности. `clinic-v2.html` = `clinic.html` + новый CSS/разметка шапки/панели/списка, **вся JS-логика (`app` объект) не тронута ни на строку**.

## Дизайн-система (что изменилось визуально)
- **Шрифты**: IBM Plex Sans (интерфейс/заголовки) + IBM Plex Mono (числа — возраст, дни, коды МКБ-10, таймстампы) вместо системного стека. Оба встроены в файл как base64 `@font-face` (файл по-прежнему самодостаточный, интернет для шрифтов не нужен).
- **Палитра**: тот же фирменный индиго-акцент (`#4f46e5` светлая / чуть светлее в тёмной — держит связь с логотипом МКНЦ), но нейтральные тона (фон/бордеры/текст) сдвинуты в холодную сторону — с лёгким индиго-подтоном, а не чистый серый. Смысловые цвета (danger/warning/good — приоритет, срок, статусы) вынесены в собственные CSS-токены (`--danger`, `--warning`, `--good` + `-soft`/`-fill` варианты), отдельно от акцента.
- **Шапка**: старый `<header>` (карточка с заголовком+юзером) заменён на `.topbar` (логотип+бренд+тема+пользователь+выход, всё в одну строку) и `.pagehead` (заголовок страницы «Пациенты» + кнопки Экспорт/Импорт/Добавить, перенесены сюда из тулбара списка).
- **Панель сводки** (бывший `.stats-bar`): та же механика сегментов, что и раньше (пропорционально/по счётчику, кликабельные фильтры), но плоские смысловые заливки вместо мягких градиентов, скругления уменьшены (6-8px вместо 10-12px), числа — моно-шрифтом.
- **Список пациентов**: карточки с тенью и скруглением заменены на плотный список с hairline-разделителями и плоской (не градиентной) левой полосой приоритета — `border-left` вместо псевдоэлемента с `linear-gradient`. Бейджи/чипы (диагноз, срок, тип лечения) — везде pill-radius (999px), код диагноза — моно-шрифтом.
- **Формы/модалки/логин**: цвета подтянулись автоматически через общие CSS-токены; отдельно поправлены места, где цвет раньше был захардкожен в hex (ломало бы тёмную тему) — инфобокс тестовых данных на логине, предупреждения о нарушенных сроках, бейджи «состоялось по плану/с отклонением».

## Что осталось идентичным
Буквально всё, что не касается внешнего вида: структура данных пациента, регламентные сроки по нозологиям, чек-лист обследований, каскадный выбор диагноза, таймлайн и переходы между этапами, экспорт/импорт (включая фильтр по заведующим), сортировки (включая «по последнему обновлению»), тайм-метки «Добавлено/Обновлено», тёмная/светлая тема, все 9 демо-пациентов и их состояние в localStorage (ключи в localStorage общие — открытие `clinic-v2.html` в том же браузере покажет тех же пациентов, что и в `clinic.html`, т.к. это один и тот же `origin`).

## Security-аудит и UX/accessibility-проход
После того как визуальный редизайн был согласован («мне нравится, давай соберём на этом дизайне»), пользователь дал отдельное задание (промт из `propt.docx`, сохранён как `propt.md`) — прогнать `clinic-v2.html` через полный технический/security-аудит и доработать UX, опираясь на рекомендации из `mukul975/Anthropic-Cybersecurity-Skills` и `nextlevelbuilder/ui-ux-pro-max-skill` (клонированы во временную папку, прочитаны выборочно — не механически, только применимые к статическому HTML/JS-стеку части). Результат задокументирован в двух новых файлах рядом с этим брифом:

- **`SECURITY_AUDIT.md`** — главная находка: stored/DOM XSS через несанированный вывод пользовательских полей пациента (ФИО, диагноз, телефон, врач, жалобы, заметки, даты событий) в `innerHTML` — реалистичный вектор не только через форму редактирования, но и через **Импорт JSON** (не валидирует содержимое полей). Исправлено — добавлен `app.escapeHtml()`, применён в 23 точках рендера (`renderPatients`, `renderPatientDetails`, `renderHistoryLog`, `renderStageEventsPanel`, `renderExportPatientList`, встраивание саммари). Проверено PoC прямо в браузере (payload в имени пациента больше не исполняется, выходит как текст). Всё остальное по чек-листу (eval/document.write, DOM-источники типа location.hash/postMessage, внешние CDN-зависимости, секреты/токены, debug-код, ссылки/redirects) — чисто, ничего не найдено. HTTP-заголовки (CSP/HSTS/X-Frame-Options и т.д.) — недоступны для статического файла, оформлены как инфраструктурные рекомендации на будущее, а не «исправлены» в коде. Клиентский логин (общий пароль в исходнике) — оставлен как есть, это уже документированное ограничение проекта, не относящееся к этой задаче.
- **`DESIGN_SYSTEM.md`** — формализует уже сложившиеся цветовые/типографские/spacing-токены проекта (см. раздел выше) + объясняет, что из `ui-ux-pro-max-skill` было взято (Pre-Delivery Checklist: контраст, focus-состояния, `prefers-reduced-motion`, брейкпоинты 375/768/1024/1440), а что сознательно отклонено (предложенная инструментом teal/зелёная палитра и шрифты Figtree/Noto Sans — конфликтовали бы с уже одобренным индиго-брендом, привязанным к логотипу МКНЦ).

Попутно по итогам UX/accessibility-прохода в `clinic-v2.html` внесены точечные правки, которых не было в исходном `clinic.html`: видимое focus-кольцо у поля поиска (раньше — только смена цвета бордера), `autocomplete="username"`/`"current-password"` на логине, `aria-label` у двух icon-only кнопок (✕ удаления события, шеврон разворота карточки), глобальный `@media (prefers-reduced-motion: reduce)` (раньше отсутствовал), и главное — узлы таймлайна этапов (кружки 1–7 в карточке пациента) были кликабельной `<div>` без клавиатурной альтернативы; добавлены `role="button" tabindex="0"` + обработка Enter/Space, проверено что клавиатурная активация меняет состояние приложения так же, как клик мышью.

Эти правки применены **только к `clinic-v2.html`** — в `clinic.html` не переносились (решение, какую версию оставлять, ещё не принято, см. «Статус» выше). Если в итоге выбор падёт на `clinic.html`, эти security/accessibility-фиксы нужно будет перенести туда отдельно — они не специфичны для нового дизайна и одинаково актуальны для обеих версий.

## Технический побочный эффект
На машине не было Node.js — он понадобился только для черновой сборки самого дизайн-макета через скилл (React/Vite-инструменты без него не работают). Поставлен через `nvm` (дописаны стандартные строки в `~/.zshrc`). На `clinic.html`/`clinic-v2.html` это не влияет — оба остаются одиночными файлами без сборки; Node.js для их работы не требуется и использовался только на этапе черновика.

## Backend-этап (2026-07-30, после согласования этого брифа)
По отдельному промту (`propt (1).docx`) поверх `clinic-v2.html` добавлен локальный
Python-backend: FastAPI + SQLite + Pydantic + Argon2id-авторизация + CSRF + строгий
импорт/экспорт + 62 pytest-теста. JS вынесен из HTML в `clinic-v2.js`; все операции с
пациентами идут через REST API, медицинские данные больше не хранятся в localStorage
(остались только тема и одноразовая миграция старых данных по явному согласию).
Пароль и список пользователей удалены из клиентского кода; экран логина упрощён до
одного поля (решение согласовано: приложение однопользовательское). Детали архитектуры
и модель безопасности — в переписанном `SECURITY_AUDIT.md`, запуск — в новом `README.md`.
**Важно**: `clinic-v2.html` теперь требует запущенный backend (см. README) и не работает
как самостоятельный файл; `clinic.html` не тронут и по-прежнему автономен. Проект теперь
под git (baseline-коммит сделан до начала правок).
