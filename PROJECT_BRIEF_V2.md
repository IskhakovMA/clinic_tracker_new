# clinic-v2 — бриф для продолжения работы

Актуально на 2026-07-30. Описывает **текущее рабочее приложение** (`clinic-v2.html` +
`clinic-v2.js` + `backend/`). Функциональная история трекера — в `PROJECT_BRIEF.md`
(осторожно: раздел «Текущий файл» там описывает архитектуру до появления бэкенда,
см. «Что устарело в основном брифе» ниже).

## Что это сейчас

Локальное клиент-серверное приложение для ведения маршрута онкопациентов:

```
clinic-v2.html   вёрстка и стили (без JS)
clinic-v2.js     весь фронтенд-код (объект app, ~2760 строк)
backend/         FastAPI + SQLite + Pydantic + Argon2id, 124 pytest-теста
clinic.html      УСТАРЕВШИЙ автономный вариант прежнего дизайна (см. «Открытый вопрос»)
```

Запуск, команды обслуживания и восстановление данных — в `README.md`.
Модель безопасности, что проверено и какие ограничения остались — в `SECURITY_AUDIT.md`.
Цветовые/типографские токены дизайна — в `DESIGN_SYSTEM.md`.

**Важно для следующей сессии**: `clinic-v2.html` больше не открывается двойным кликом —
без запущенного бэкенда будет пустой экран логина без возможности войти. Данные пациентов
лежат в SQLite (`backend/data/clinic.db`), не в браузере.

## Как проект пришёл к текущему виду

**Этап 0 — функционал** (см. `PROJECT_BRIEF.md`): один автономный HTML-файл, данные в
localStorage, клиентский логин-гейт с общим паролем `'password'` в исходнике.

**Этап 1 — редизайн** (`clinic-v2.html`): дизайн применён поверх копии `clinic.html`, а не
переписан с нуля на React — так не потерялась накопленная функциональность. Изменился только
внешний вид (см. следующий раздел), вся JS-логика осталась байт-в-байт. Тогда же прошёл первый
security-аудит: найден и исправлен stored/DOM XSS через несанированный вывод полей пациента
(`escapeHtml()` в 23 точках), плюс UX/accessibility-правки — focus-кольцо у поиска,
`autocomplete` на логине, `aria-label` у icon-only кнопок, `prefers-reduced-motion`,
клавиатурная активация узлов таймлайна.

**Этап 2 — бэкенд** (промт `propt (1).docx`, ветка `feat/secure-clinic-backend`): FastAPI +
SQLite + Pydantic. Пароль и список пользователей удалены из клиентского кода, авторизация
серверная (Argon2id, серверные сессии, CSRF), медицинские данные переехали из localStorage в
SQLite, импорт переписан на строгую схему с preview→подтверждение→транзакцию, экспорт — только
после авторизации, добавлены security-заголовки. JS вынесен из HTML в `clinic-v2.js`. Экран
логина упрощён до одного поля пароля — **согласованное решение**: приложение однопользовательское,
прежние три «учётки» были лишь подписью в шапке и не разграничивали доступ.

**Этап 3 — hardening** (промт `propt (3).docx`, ветка `security/frontend-csp-hardening`):
устранены все ~44 inline `on*=`-обработчика, `innerHTML` (11 точек) заменён на
`createElement`/`textContent`/`replaceChildren`, функции `escapeJsAttr`/`escapeHtml` удалены как
ненужные, CSP запретила inline-скрипты полностью (`script-src-attr 'none'`). Добавлены:
обезличенный журнал аудита (`audit_events`), инвалидация всех сессий при смене пароля, политика
слабых паролей, кроссплатформенные `check-db`/`backup`/`restore` через SQLite backup API. Тестов
стало 124.

## Дизайн-система (что отличает v2 визуально)

- **Шрифты**: IBM Plex Sans (интерфейс) + IBM Plex Mono (числа — возраст, дни, коды МКБ-10,
  таймстампы) вместо системного стека. Встроены как base64 `@font-face` — интернет не нужен.
- **Палитра**: тот же фирменный индиго-акцент (`#4f46e5`, связь с логотипом МКНЦ), но нейтральные
  тона сдвинуты в холодную сторону (лёгкий индиго-подтон вместо чистого серого). Смысловые цвета
  вынесены в отдельные токены `--danger`/`--warning`/`--good` (+ `-soft`/`-fill`), независимые от акцента.
- **Шапка**: `.topbar` (логотип + бренд + тема + статус сессии + выход в одну строку) и `.pagehead`
  (заголовок «Пациенты» + кнопки Экспорт/Импорт/Добавить).
- **Панель сводки**: та же механика кликабельных сегментов-фильтров, но плоские заливки вместо
  градиентов, скругления 6–8px, числа моно-шрифтом.
- **Список пациентов**: плотный список с hairline-разделителями и плоской левой полосой приоритета
  (`border-left`), бейджи/чипы с pill-radius 999px.

## Что не менялось за все три этапа

Вся предметная логика: структура данных пациента, регламентные сроки по нозологиям, чек-лист
обследований, каскадный выбор диагноза (локализация → МКБ-10), таймлайн из 7 этапов и переходы
между ними, фильтры (приоритет/этап/срок/заведующий), сортировки, тайм-метки «Добавлено/Обновлено»,
саммари для отчётности, тёмная/светлая тема. Формат данных пациента совместим со старым экспортом —
JSON из localStorage-версии импортируется (одноразовая миграция или обычный импорт).

## Что устарело в основном брифе (`PROJECT_BRIEF.md`)

Файл не переписывался и остаётся источником по функционалу, но эти утверждения больше не верны
для `clinic-v2`:
- «Единственный файл проекта… без сервера, работает полностью офлайн. Данные — в `localStorage`» —
  теперь бэкенд обязателен, данные в SQLite.
- Раздел «Доступ с телефона» (открыть файл в Safari) — неприменим: нужен доступ к запущенному
  бэкенду по сети, а это требует HTTPS reverse proxy (см. README).
- Упоминания демо-пациентов и `getDefaultPatients()` — функция удалена, база стартует пустой.
- Ограничение «клиентский логин с общим паролем» — исправлено на этапе 2.

## Открытый вопрос: `clinic.html` vs `clinic-v2.html`

Решение по дизайну **всё ещё не принято**, но цена вопроса изменилась: этапы 2 и 3 (бэкенд,
серверная авторизация, аудит, CSP, тесты) сделаны **только для `clinic-v2`**. `clinic.html`
остался нетронутым автономным файлом прежнего дизайна — с паролем в исходнике, данными в
localStorage и inline-обработчиками.

- Если выбор — **v2**: удалить `clinic.html`, перенести историю дизайн-решений в `PROJECT_BRIEF.md`
  и актуализировать в нём устаревшие разделы (см. выше).
- Если выбор — **старый дизайн**: это не «удалить лишний файл», а перенос всей работы этапов 2–3
  на другую вёрстку (примерно: переразметить шапку/панель/список под старые стили, оставив
  `clinic-v2.js` и бэкенд как есть). Существенный объём — стоит обсудить до начала.

Самостоятельно не удалять и не сливать ни один из файлов.

## Технический побочный эффект

Node.js на машине не было — поставлен через `nvm` (стандартные строки в `~/.zshrc`) на этапе 1
для черновой сборки дизайн-макета. Сейчас используется только для `node --check clinic-v2.js`
в проверках; для работы приложения не требуется. Python-окружение — `.venv` в корне проекта
(в Git не попадает).

## Что дальше

Следующий запланированный этап — **UI/UX-редизайн** (пользователь сказал, что задача будет
отдельной; на этапе 3 к нему сознательно не переходили). Полезно учесть:
- Стили сейчас — inline `style=`-атрибуты в разметке и в JS-хелперах; из-за этого в CSP остаётся
  `style-src 'unsafe-inline'`. Вынос стилей в CSS-файл закрыл бы это ограничение — естественная
  часть редизайна.
- Фронтенд после этапа 3 строится через DOM-хелперы `el()`/`frag()`/`option()` в начале
  `clinic-v2.js` — новые компоненты писать так же, HTML-строки и inline-обработчики не возвращать
  (это ломает CSP и падают тесты `test_frontend_csp.py`).
- Экран аудита в UI намеренно не делали (есть `GET /api/audit` и `python -m backend.cli audit-tail`) —
  если он нужен, это задача редизайна.
